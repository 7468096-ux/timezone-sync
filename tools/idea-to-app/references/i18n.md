## Rules

- **No hard-coded user-visible text** anywhere in components: `t("key", { vars })`. Missing key falls
  back to English, then to the key (so a missing translation is visible but never crashes).
- Add every new key to **all 10** languages in the same change. Write real translations, natural
  for the language (not word-for-word); keep them short — buttons must fit on a phone.
- Detect: saved choice → `navigator.languages` → English. Save on change. Apply to `<html lang dir>`
  so per-script CSS kicks in; update `document.title`.
- **Numbers and times use Latin digits** in every language (`-u-nu-latn`), so clocks and grids align.
  Use `Intl` for units, durations, weekdays, dates (`fmtDuration`, `fmtWeekday`, `fmtNumber`).
- Templates with controls inside a sentence ("from {from} to {to}"): `splitTemplate()` splits the
  string so selects sit where each language puts them.
- **RTL:** the page mirrors (use logical properties: `inset-inline-end`, `text-align: start`), but
  times, ranges, codes and time grids stay LTR (`direction: ltr; unicode-bidi: isolate`). Mirror
  directional UI like the switch knob, and arrows inside text ("Anna → Boris" becomes ← in Arabic: flip
  with CSS `[dir="rtl"] .arrow { transform: scaleX(-1) }` and use "←" in generated chat text).
  Check Arabic at 390 px every time.
- Scripts without letter case (zh, hi, bn, ar): no `text-transform: uppercase`, no letter-spacing
  (it breaks Arabic joining); use the text face instead of the Latin mono for labels.
- The product name stays Latin (`lang="en" dir="ltr"` on the eyebrow).
- Example data on first visit is in the visitor's language (names, roles), with real places.
